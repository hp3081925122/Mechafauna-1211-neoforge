# Mechafauna 迁移至 Minecraft 26.1.2 NeoForge

## 目标与基线

- 源项目：`E:\模组\发cf的模组\生物\机械\Mechafauna-1211-neoforge`，分支 `main`，Minecraft 1.21.1、NeoForge 21.1.233、Java 21、GeckoLib 4.8.4。
- 目标项目：`E:\模组\发cf的模组\生物\机械\Mechafauna-2612-neoforge`，Minecraft 26.1.2、NeoForge 26.1.2.95、Java 25、GeckoLib 5.5.2，基于对应的本地模组模板。
- 保持 `mechafauna` 命名空间及已有注册 ID；不修改源项目中的既有行为，不做旧版本世界/存档兼容，不以删减功能换取迁移速度。

## 必须保留的功能

- 13 个实体注册：可骑乘机械狼、机械狼、坦克、机械无人机、军用无人机、自爆蜘蛛、重装机甲、火焰爬行者、棱镜哨兵、飞碟 Boss、飞碟激光打击、机甲投射物、棱镜光束。
- 物品、盔甲、刷怪蛋、创造物品栏、合成配方、战利品、伤害类型、粒子、音效、配置，以及两种结构及其生成数据。
- 生物 AI、目标选择、移动与攻击逻辑；坦克/机甲的枪弹与导弹、蜘蛛自爆、无人机控制、飞碟武器独立受损和分节破坏、Boss 血条与音乐等现有玩法。
- GeckoLib 模型、贴图、动画、盔甲、手持机枪与导弹渲染；网络 payload、客户端按键/渲染事件及玩家骑乘无人机的 Mixin 行为。
- 当前源码、资源、模型和数据文件全量迁移；不得遗漏新增生物、掉落、创造栏或结构内容。

## 迁移步骤

1. 从 `E:\模组\模组模板\2612-neoforge` 创建独立目标工程；保留原项目不动，排除 `.gradle`、`build`、`run`、`runs`、IDE 缓存和日志。
2. 将模组 ID、注册、配置、事件、实体、物品、AI、伤害、投射物、网络、GameTest 与客户端代码逐项迁入，按目标版真实源码/API 改写；功能行为以源项目为对照，不保留旧版兼容分支。
3. 使用 Java 25、ModDevGradle 和 NeoForge 26.1.2.95 重建 Gradle 配置及模组元数据。核对 Mixin 与枚举扩展在目标版的加载方式；Jade 目前只见于构建依赖、源码未发现调用，确认无运行时用途后才移除该依赖。
4. 将 GeckoLib 升至 5.5.2，按目标版调用签名重写模型/渲染器；模型迁至 `assets/mechafauna/geckolib/models/`，动画迁至 `assets/mechafauna/geckolib/animations/`，逐一核实 Java 返回的资源标识与文件名。
5. 迁移语言、物品模型、贴图、声音、粒子、配方、战利品、标签、NBT 结构、结构池/结构集和测试，并检查引用路径、注册 ID、客户端/服务端隔离。

## 验收标准

- `clean build` 成功；测试与 GameTest 能在目标版执行；打包 JAR 中包含所有目标资源且没有模板示例内容。
- `runClient` 启动无缺失注册、Mixin、GeckoLib 模型/动画、纹理或配方错误；创造栏、刷怪蛋、物品模型和盔甲显示正常。
- 实机逐项验证 13 个实体及其移动、索敌、朝向、攻击、受击、死亡/破坏行为；验证骑乘无人机控制、机甲枪弹/导弹、Boss 分节与独立武器破坏、血条/音乐、结构生成。
- 服务端启动及至少一次多人客户端连接验证网络同步和服务端专属逻辑；迁移失败项必须记录，不能以编译通过代替实机验收。
